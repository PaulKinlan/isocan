          What it can reach locally

          Its memory
          Facts it was asked to remember live in this browser's own store — navigator.storage.getDirectory(), the OPFS file voice/memories.json — this origin only, not the terminal and not another browser or profile. It asks the browser to keep the store (navigator.storage.persist()); when that is refused the entries last only for the tab, and Memory in the cog says so. Every entry is listed there and yours to delete.
          One folder you chose
          Files are reachable only through the folder you pick with showDirectoryPicker({ mode: "read" }), remembered as a DirectoryHandle. The harness is told the folder's NAME over POST /fs/grant and never gets the handle. list_dir and read_file walk inside that folder and nothing else, read-only; .. and absolute paths are refused. No folder granted, no file read.
          The provider key
          Presence, never the value. The page posts it once over loopback and keeps no copy; the harness holds it at ~/.isocan/voice/key.json with mode 0600. Settings says whether one is stored; no surface shows the key itself.
          The project's own instructions
          If the directory bound to this canvas holds an AGENTS.md (or CLAUDE.md), its first 12,000 characters are read at session start and given to the model. Nothing else in that directory is read, and a directory whose .isocan/project.json is not this canvas is not touched.
          Your microphone
          getUserMedia({ audio: true, video: false }) while the session is live, and the device list from enumerateDevices(). Capture stops when you press End. The camera is never asked for.
          The harness's own record
          Its tool calls and events are written beside its key — ~/.isocan/voice/log.json and harness.log, mode 0600 — and are what Logs shows.

          What it can reach remotely

          The model provider
          Everything the model hears, and everything it is told, goes to Google's Gemini Live API: wss://generativelanguage.googleapis.com …BidiGenerateContent, the model named in Settings — including what it reads back from the canvas, from the folder you granted and from its memories. Your audio only ever leaves through the harness.
          The daemon
          Operations are sent to the daemon: http://127.0.0.1:4441 by default, or whatever ISOCAN_HOME, ISOCAN_PORT or this canvas's .isocan/project.json names — a hosted home such as dev.isocan.io is one of the possibilities. Settings names the daemon in play; the page cannot choose one, only ask the harness to switch.
          Other people
          A canvas may be shared, and one replicated to another daemon is served there by that daemon (isocan who shows the replicas relaying). Everything the agent does lands on the canvas as the enrolled actor's work, and the log behind Logs keeps the record.
          The tab it opens
          Open the project asks the harness for a one-use pass (GET /open) and opens the canvas on the daemon's own host, with the pass in the URL fragment (#pss_…).
          What the page itself talks to
          Nothing but the harness, over the same-origin /harness path — the page holds no key and has no socket to the daemon.

          What it cannot do, and why

          • Delete a canvas, or empty the trash — confirmation-gated. The harness asks you in the page (POST /confirm) and waits for your press; a force: true the model adds to its own call is not consulted, so it cannot sign its own permission slip.
          • Remove a version, remove a comment, or restore a deleted thread — refused by the engine: INTERNAL_OP_TYPES in packages/core/src/ops.ts is the set clients may not send, because each of those is an undo inverse rather than an act a person performs.
          • Rename itself, or choose its own identity — no tool sets the actor's name. It is claimed once, when the harness starts (isocan voice --as <name>); colour and mark are the model's to change.
          • Delete a memory — the memory tools are remember, read_memory and search_memory; nothing removes one. It can read everything stored — a search with no words lists them, 50 in one answer — and forgetting is the button in the cog, which is yours.
          • Read anything outside the folder you granted — the file tools take a path relative to the grant and walk it through the handle. There is no absolute path, no home directory and no shell.
          • Reach beyond its declared tools — the model has LIVE_TOOLS and nothing more: no terminal, no arbitrary fetch, no second vocabulary that could disagree with the CLI.
