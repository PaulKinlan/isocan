Wasm tool surface — hash.wasm (SHA-256)

What this is. One real wasm tool — a SHA-256 compiled in this repo from tools/wasm-tools/sha256.c — uploaded to the daemon's content store, with its digest pinned as a project property and verified before every load. One button flips a byte so you can watch the load refuse.

What this is not. Not the admission system, not the pin store, not production parity. The pin lives as a project property — option A, a stand-in for the open decision. The module is pure: no imports, no network, no clock — the refusal you can trigger below is the mechanism.

What this does not prove. The check is bytes-vs-pin, and the pin arrives from the same daemon as the bytes — a server serving a malicious module and a matching pin would pass. This page proves the loader verifies; it does not attest who to trust, and wasm here is not a sandbox. Any input you type can be checked against sha256sum — on more than one input.

The refusal — the mechanism

Corrupt the bytes and run the same load path. A verifier that cannot refuse is decoration.

The load path, every time: fetch bytes by hash → SHA-256 them in the browser (crypto.subtle) → compare to the pin → only then instantiate. Nothing here re-runs a computation from a log; nothing here runs a module whose bytes do not match the pin.
