# 12 September 2026

## A microphone check before a voice agent

`/voice-check` is a small capture-only page, usable before sign-in or provider
configuration. It shows the actual input level, records up to ten seconds and
plays the local sample through native audio controls. Reset, page hiding and
exit release capture and discard the recording. There is no provider client,
key, token mint or model call in this slice.

Chrome 152.0.7977.82 exercised the mic-only JS path using a fake stepped-tone
device: audio acquired without video, a changing meter, a decodable recording,
playback and cleanup. Denial ran separately without the auto-accept flag. A
headful run captured the browser's native microphone permission prompt.
Browser-page traffic was same-origin GETs without request bodies, plus local
blob playback; this is not a claim about Chromium's background traffic.

The previous day's [permission correction](2026-09-11.md) remains explicit:
modern `<usermedia>` asks for camera and microphone, so the page skips it.
A real `<microphone>` is preferred when supported; that branch was not
available in the tested browser. No legacy flag or relaxed audio-only guard
was used to manufacture support.

This is not speech recognition or voice control. The [Live slice](../projects/voice-interface/browser-ui.md)
— daemon-minted ephemeral token, transcript, then one native operation —
remains gated on explicit activation. Real microphone/speaker quality must
still be tried on the person's own setup.
