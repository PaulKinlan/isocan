# 13 September 2026

## The help dialog, generated so it cannot start lying

Paul: *"I need a help dialog (similar to cog) that describes all the
functionality including tool calls etc and what it can access locally as a
harness as well as remotely via the isocan."* That is a lot of trust to ask
for in one page — a microphone, a folder, an API key, a persistent store, and
an agent acting on canvases other people can see — and until tonight the page
said nothing about any of it.

**A third dialog, not a third shell.** The help button sits beside the cog and
the logs and opens the same native `.voice-dialog`: `closedby="any"` with the
Safari fallback, sticky head, flat sections, one scroll container, focus
restored to the button that opened it. The only real change to the shared
machinery was the light-dismiss fallback, which used to pick between two
dialogs by name (`settings.open ? settings : logs`) and now finds the open one
among three; a test presses outside the help dialog's box while the cog is up,
because the picker choosing the wrong box is the bug that edit could have
introduced.

**The section that decides whether this is a help page or a wish list is
generated.** `scripts/voice-capability-sweep.mjs` already derived the ledger in
`docs/projects/voice-harness/capability-sweep.md` from five surfaces and
computed its own counts; it now reads a sixth, and writes a second output.
The sixth is the harness's own `LIVE_TOOLS` in `packages/cli/src/voice-harness.ts`
— the statement that matters most to a person reading this dialog, and the one
list nobody had merged in: memory, files, and the 42 acts the model can
actually call. Its NAMES are parsed out of the source rather than retyped, so a
tool added there reaches the dialog without anyone editing the page. The ledger
went from 145 rows to **187 — 124 tooled, 34 missing, 29 excluded** — and those
numbers are computed from the rows, never typed. The brief handed to this lane
said 87 tooled and 29 missing; both were stale readings of the same ledger,
which is precisely why the rule is *derive it* rather than *write it down*.

The second output is `packages/web/src/voice/capabilities.generated.ts`:
groups of acts in the words a person would use (`item_add_version` is "keep an
item's text as a new version"), deduped by tool because `add_item` appears
eight times across five surfaces, and total — anything the grouping rules do
not name lands under "Also available" rather than vanishing. The refusals come
from the same rows, so the confirmation-gated and internal operations are
stated by the ledger and not by memory. `--check` fails when either output is
stale; `packages/web/test/voicehelp.test.ts` runs it (proved by hand-editing a
count and watching the test name the file to regenerate) and then asserts the
rendered dialog shows exactly what the generated data says.

**What cannot be generated is anchored instead.** The local and remote sections
are prose, but every claim names the mechanism it describes — the OPFS call and
`voice/memories.json`, `showDirectoryPicker({ mode: "read" })`, `POST /fs/grant`,
`~/.isocan/voice/key.json` at `0600`, `AGENTS.md` at 12,000 characters,
`getUserMedia({ audio: true, video: false })`, `ISOCAN_PORT` and the default
`127.0.0.1:4441`, `wss://generativelanguage.googleapis.com`, `INTERNAL_OP_TYPES`
in `packages/core/src/ops.ts` — and one table-driven test asserts each mechanism
is still in the source file it belongs to. A claim whose mechanism moved fails
the test, so somebody rewrites the sentence instead of leaving a comfortable
lie. Two claims in the brief did not survive being checked: the model is not
refused the camera by policy but by construction (the video-bearing
`<usermedia>` element is deliberately not in the capture ladder), and it *can*
enumerate memories — `search_memory` with an empty query lists everything
stored — so the dialog says it reads them all and cannot delete one, which is
the true boundary. "Cannot" written carelessly is still a lie.

**Evidence.** Eight new jsdom tests; the whole web package except five files
that were already red on this branch's base (tool-rail tooltips, the canvas
list, the narrow-window minimap, the switcher — all reproduced with this work
stashed). Then the real page in Chrome: opened from the keyboard (Tab, Enter),
closed with Escape with focus back on the button, at 1440 and 420, light and
dark, scrolled to the end — 42 acts, 6 limits, 29 refusals, no horizontal
overflow at 420 — and the six screenshots reviewed by a vision model, which
found the text legible and nothing clipped at either width. It named one thing
left alone on purpose: the sticky head slices the line scrolling under it with
no fade, at 420 more visibly than at 1440. That is the shared shell the cog and
the logs already wear, and this dialog extends it rather than forking its look;
the finding belongs to the shell, not to this section.
