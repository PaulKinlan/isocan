# 18 September 2026 — A stranded claim, and the wrong remedy printed beside it

The `roadmap-sync` timer had been failing for eight days. Its canvas, Roadmap
Test, was frozen at `434c9198` (10 Sep) while `origin/main` had moved 98
commits past it. The reason was one line in the service's own stderr:

    no actor is claimed under session "cron:roadmap-sync" — claim it once:
    ISOCAN_HARNESS=cron ISOCAN_SESSION_ID=roadmap-sync isocan identity --name "Your Name" --session

The actor *was* claimed. `Roadmap Sync` (`usr_AgRvjzUbIN`) had been claimed
under that exact key on 10 September — and the claim was still on the desk,
held by `bdg_f9YL8cthAI`. This machine re-badged on 12 September; the live
badge `bdg_ep0NQZDaZC` held five claims and not that one, and the migration
shelf was empty, so there was no legacy row left to adopt. The claim had not
been lost. It had been stranded on a badge nobody holds.

That is the case `noIdentityHere` was written for, and it says so plainly: the
identity IS configured, it is just not reachable from here, and `--name` would
mint a stranger wearing the same name and leave the history behind — "the
precise mistake `--as` exists to prevent". The ambient walk got that answer.
A script stating its own identity did not, because `connect()` printed a fixed
gesture and never asked the desk anything. So the timer's error advised the one
recovery that would have made the damage permanent: a second `Roadmap Sync`,
refused as name-taken, or admitted and splitting every later version and every
`undo` across two actors.

`connect()` asks now. The explicit-identity refusal looks up
`/api/actors/orphaned` for the one key the caller stated — key-scoped, so the
answer can never be a roster — and when that key is claimed on a badge this
machine no longer holds, it names the actor and prints `--as <actorId>` instead
of `--name`. A home that cannot answer degrades to the old generic gesture
rather than failing the refusal. The helper is private to `connect.ts` on
purpose: the API ceiling in `test/entry.test.ts` counts names a caller outside
the package needs, and this one has exactly one caller, inside it. Nothing
asserted the old message, and the new test is red without the fix — it
reproduces the eight-day stderr verbatim.

The recovery itself was the daemon's own sentence, run once:

    ISOCAN_HARNESS=cron ISOCAN_SESSION_ID=roadmap-sync isocan identity --session --as usr_AgRvjzUbIN

The timer's next scheduled fire, eight seconds later, did the rest: 109
operations in 90 seconds, every one of them stamped `Roadmap Sync`
(`usr_AgRvjzUbIN`) and none anonymous, 56 documents rewritten and 30 cards
added, the canvas caught up to `a770255c`. Checked against the repository
rather than against the script's own log: all 103 documents the current
`docs/ROADMAP.md` links now match `origin/main` byte for byte, by blob hash.
One card did not move and should not have — `docs/projects/memory/design.md`
left the roadmap table at `b5755f08`, and a file that leaves the roadmap
leaves its card behind, because nothing here deletes. The fire after that ran
quiet in 1.5 seconds: 103 tracked, 0 changed, exit 0.

The wider lesson is the part worth keeping. A refusal that names a remedy is
only as good as the remedy, and this one was confidently wrong for the single
case most likely to reach it — a long-running script whose badge outlived
itself. The desk already knew the truth; the door just was not asking.
