# 18 September 2026 — A stranded claim, and the wrong remedy printed beside it

The `roadmap-sync` timer had been failing for eight days. Its canvas, Roadmap
Test, was frozen at `434c9198` (10 Sep) while `origin/main` had moved 98
commits past it. The reason was one line in the service's own stderr:

    no actor is claimed under session "cron:roadmap-sync" — claim it once:
    ISOCAN_HARNESS=cron ISOCAN_SESSION_ID=roadmap-sync isocan identity --name "Your Name" --session

The actor *was* claimed. `Roadmap Sync` (`usr_AgRvjzUbIN`) had been claimed
under that exact key on 10 September — and the claim was still on the desk,
held by `bdg_f9YL8cthAI`. This machine re-badged on 12 September; the live
badge `bdg_ep0NQZDaZC` held five claims and not that one, and the migration
shelf was empty, so there was no legacy row left to adopt. The claim had not
been lost. It had been stranded on a badge nobody holds.

That is the case `noIdentityHere` was written for, and it says so plainly: the
identity IS configured, it is just not reachable from here, and `--name` would
mint a stranger wearing the same name and leave the history behind — "the
precise mistake `--as` exists to prevent". The ambient walk got that answer.
A script stating its own identity did not, because `connect()` printed a fixed
gesture and never asked the desk anything. So the timer's error advised the one
recovery that would have made the damage permanent: a second `Roadmap Sync`,
refused as name-taken, or admitted and splitting every later version and every
`undo` across two actors.

`connect()` asks now. The explicit-identity refusal looks up
`/api/actors/orphaned` for the one key the caller stated — key-scoped, so the
answer can never be a roster — and when that key is claimed on a badge this
machine no longer holds, it names the actor and prints `--as <actorId>` instead
of `--name`. A home that cannot answer degrades to the old generic gesture
rather than failing the refusal. The helper is private to `connect.ts` on
purpose: the API ceiling in `test/entry.test.ts` counts names a caller outside
the package needs, and this one has exactly one caller, inside it. Nothing
asserted the old message, and the new test is red without the fix — it
reproduces the eight-day stderr verbatim.

The recovery itself was the daemon's own sentence, run once:

    ISOCAN_HARNESS=cron ISOCAN_SESSION_ID=roadmap-sync isocan identity --session --as usr_AgRvjzUbIN

The timer's next scheduled fire, eight seconds later, did the rest: 109
operations in 90 seconds, every one of them stamped `Roadmap Sync`
(`usr_AgRvjzUbIN`) and none anonymous, 56 documents rewritten and 30 cards
added, the canvas caught up to `a770255c`. Checked against the repository
rather than against the script's own log: all 103 documents the current
`docs/ROADMAP.md` links now match `origin/main` byte for byte, by blob hash.
One card did not move and should not have — `docs/projects/memory/design.md`
left the roadmap table at `b5755f08`, and a file that leaves the roadmap
leaves its card behind, because nothing here deletes. The fire after that ran
quiet in 1.5 seconds: 103 tracked, 0 changed, exit 0.

The wider lesson is the part worth keeping. A refusal that names a remedy is
only as good as the remedy, and this one was confidently wrong for the single
case most likely to reach it — a long-running script whose badge outlived
itself. The desk already knew the truth; the door just was not asking.

## The WebMCP co-browsing transport is designed, from an executed census

The September 11 registration described an MCP vocabulary of six read tools and
a browser API named `navigator.modelContext`, and said the write half waited on
addressability. All three were stale, so the design re-ran the census before
arguing from it: a real stdio handshake against the shipped server answered
**sixteen** tools — re-counted behaviourally in the corrected census as **eleven
non-mutating and five mutation/claim** (the earlier ten/six split was a grouping
of the inventory, not behaviour, and this entry had it both ways until 18 Sep) — and the
browser API was measured on two Chromes rather than read — `document.modelContext`
is present by default on Chrome for Testing 150.0.7871.24 and behind
`--enable-features=WebMCP` on stable 152.0.7977.82, `provideContext()` is gone,
and the spec now carries four annotation hints where the registration said there
were none. Two behaviours phase 1 must carry came out of running it, not reading
it: `executeTool` rejects an object argument (`Failed to parse input arguments`)
and accepts a JSON string, and that `getTools()` retains `readOnlyHint` and
`untrustedContentHint` while omitting `consequentialHint` and `debugging` even
when they are set true. The projection behaviour was observed; the rule behind
it is undetermined, and no phase rests on the hint. An earlier revision of this
entry claimed `getTools()` "elides false annotation hints" — it does not, and
that claim is superseded here.

`docs/projects/webmcp-cobrowsing/design.md` argues the transport: the sixteen
tools moved into the page the human is already on, the MCP identity behaviour as
actually measured (an unclaimed ambient session may write; a claimed session is
a distinct actor; a missing explicit session is refused — whether the write half
is separately addressable or undoable is *not* established by that measurement
and is left open), deixis taken from the live selection on the ephemeral plane,
every authored text marked `untrustedContentHint`, canvas writes simply not
returned as consequential in the projection (the reason is undetermined, and no
phase claims one), and graceful absence where the API is not enabled. `phases.md` is the six-phase walk, each phase with the
browser acceptance that closes it and the observation that falsifies it.
`journey.md`'s dated census lines and owed list were corrected in place.

## The roadmap timer's definition and its recovery are tracked

`docs/ROADMAP.md` has been mirrored onto the Roadmap Test canvas by a user timer
since 10 September. Everything that defines that timer — the 274-line `sync.mjs`,
its README, the two systemd units, the published-package dependency — lived only
in one machine's home directory, outside every repository. Nothing about it could
be reviewed, backed up, or handed to a second person.

That cost eight days. On 10 September the machine re-badged; the timer's claim
(`cron:roadmap-sync`) stayed on the home's desk, on a badge nothing held any more.
The refusal the script printed on every fire advised
`isocan identity --name "Your Name" --session` — which would have minted a second
`Roadmap Sync`, either refused as name-taken or admitted and splitting every later
version and every per-actor `undo` across two actors. Nobody followed it, and the
canvas simply stopped moving while `origin/main` moved 98 commits past the commit
the canvas named.

The recovery was run for real today: the same session key, `--as` rather than
`--name`, which the desk deliberately excludes from “held elsewhere”, so no vouch
was needed. The timer's own next scheduled fire landed 109 operations in 90
seconds, every one stamped with the actor it resumed and none anonymous; the fire
after that was quiet in two seconds. The four steps, the trap and the verification
— read off the persisted canvas rather than the script's own log — are in
[`docs/projects/roadmap-canvas/runbook.md`](../projects/roadmap-canvas/runbook.md),
with the timer's definition of record beside it under
[`roadmap-sync/`](../projects/roadmap-canvas/roadmap-sync/): the script, both
units, the package manifest and the operational README, which now carries the
recovery section the live copy lacks.

The wrong advice at its source is fixed separately: `packages/api/src/connect.ts`
now asks the home for the single session key the caller stated and prints
`--as <actorId>` when that key is claimed on a badge nobody holds, degrading to
the old generic gesture when the home cannot answer (`isocan-irs`, in review).
Until that reaches the published release the timer consumes, the runbook's first
step — `whoami` under the timer's own key, which already names the stranded actor
— is the way an operator finds the id.

The plan the timer is the manual form of — journey, design and phases for the
roadmap canvas itself — is still owed by its epic; the directory now holds the
operating half that had been living nowhere.
