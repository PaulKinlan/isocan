## What landed

### feat(server): a local delivery ledger for attempts that were made and lost (isocan-k82)

`263ae54`

The oplog cannot answer "did my edit land?", and it must not: the oplog is the
canvas's shared, replicated, UNDOABLE history — entries attributed to a person,
replayed on their peers, reversible. A delivery failure is true only on the
machine that failed, is not a fact about the canvas, and must never be replayed
by anyone else. Recording it there would either be a lie on every other peer's
copy or an entry an undo leaves behind.

So the record lives beside the daemon's other machine-local state, and this is
the smallest complete piece of it:

- `delivery-ledger.ts`: append-only JSONL at ~/.isocan/delivery.jsonl, one row
  per loss (`at`, `canvasId`, `homeUrl`, `cause`, `outcome: "not-made"`). The
  append NEVER throws — a courtesy that costs the 503 its answer is not a
  courtesy. A missing file is an empty ledger, not a broken daemon.
- `HomeUnreachableError` now KEEPS the homeUrl and cause it was constructed
  with. It already told the truth in its message ("the write was NOT made"),
  but only in prose, so a reader of the ledger would have had to parse a
  sentence to learn which home this was about.
- The 503 branch in http.ts records the row. That branch is the one place every
  attempt-and-loss passes through — it is the only place that has to change for
  the record to be complete for every path.

Tests assert the contract a reader relies on: one row per loss, and APPENDED —
the third loss does not erase the first. Falsified by mutation: replacing
appendFileSync with writeFileSync (keeping only the most recent loss) turns
"appends rather than replacing" red. Also verified: an unwritable path throws
nothing.

Not in this commit: the reader. `isocan home` should render the row beside the
canvas's home state, as a sentence a person can act on. A record written but
unread is the next slice, not this one — and this one is honest without it.

Also in this commit: deliveryLedgerPath is NOT exported. The unused-exports
ceiling caught it at 41 past the agreed 40, and the gate refused the push before
the suite was even read — the gate working twice in one change.
