# 19 September 2026 — The canvas card stops polling and joins the room

Two changes to the way a canvas card draws another canvas, from one
reconnaissance that found the 10 September prototype for the second was
already wrong before it was ever finished.

**The card is a room member, not a poller** (isocan-wq6.6). A card on a
hosted store pulled the other canvas's snapshot every thirty seconds while
its tab was visible — N cards on a wall meant N pollers reading snapshots
forever, for pictures that change a few times a day. The engine has kept
per-canvas rooms since the beginning (`server/ws.ts` is snapshot-then-tail
on purpose), so the card now dials the room it is showing
(`useCanvasTail`): one snapshot on hello, then every mutation as it lands,
folded through the same reducer every other client uses. A CLI rename
reaches the card in one broadcast instead of the next pull, and the wall's
cost moves from N requests every half-minute to N sockets. The card is a
read-only member and says so honestly: it never sends presence, so the
server never registers a face for it; "N here" comes from the rosters the
room broadcasts anyway. Every dial says `since=0` — no cursor claims, no
second resume path to keep honest. Recovery is close-and-redial; a fold
that will not apply closes the socket, as does a second heartbeat that
finds the card still behind the same tip (the #85 two-beat rule); the door's
refusals (4401/4402, 4403/4404/4426) map onto the card's existing
sentences; and a card whose home is elsewhere keeps the old pull, because
its room is not here to dial.

**The picture gained exactly one extra level** (isocan-wq6.5, the fork-side
answer to upstream #203's aggregation gap — forty canvases used to be forty
cards, each a card and never a place). Inside a card's picture, a nested
canvas block now deepens into the referenced canvas's own picture: at most
40 items, one level and no further, only while the tab shows it, and only
when the drawn box is big enough to read — below that, the titled block is
the honest rendering. The whole gate is one pure function (`canDeepen`) so
it is unit-tested as behaviour instead of grepped as source; cycles cannot
deepen (the ancestor set, and the op vocabulary already refuses
self-placement); and the nested pull goes through the source-snapshot
policy path with the automatic-exclusion header, never a raw snapshot
bypass — the original prototype did bypass it, which would have misread
personal canvases, and was reworked rather than rebased.

**The bug the tests caught before the browser did.** The tail's fold helper
originally returned the folded state without writing it back into the
holder, so every op folded from the original snapshot instead of the
accumulated picture — a card would have shown only the last op's effect,
and only the unit test on the fold caught it, because the browser drive
happened to land ops that looked plausible either way. It is the fourth
time here a suite that could fail has earned its keep over a suite that
could not, and the reason the prototype's source-string "tests" were
replaced rather than carried over.

**Driven, not served.** Both changes were verified against the built app on
an isolated daemon: a CLI rename and an item add reached two cards on a
wall in seconds with no reload, while the snapshot endpoint was fetched
exactly twice (the initial paints) across forty-plus seconds — the old
cadence is gone, not throttled. Standing up that isolated stack also found
its own bug, filed separately (isocan-vab): a daemon whose configured home
URL is its own origin dials itself forever and leaks tens of thousands of
established sockets machine-wide.
