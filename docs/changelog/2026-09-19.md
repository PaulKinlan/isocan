# 19 September 2026

## Repository roadmaps through Add and the CLI

`isocan roadmap add owner/repository` and the app's Add field now read a public
repository's `docs/ROADMAP.md` into ordinary Markdown cards. One summary and one
heading per source section accompany the rows. Both clients use the same core
recogniser, GFM parser, card plan and landing helper. One undo removes the import.

The reading resolves a commit before fetching the file. GitHub's contents `sha`
is a blob ID, so it is kept separately and checked against the downloaded bytes;
it never becomes the ref in a document link. Every card names the repository,
path, commit and read time. Row documents are pinned to that commit; named issues
have links, while `see` remains source-authored words.

Derived content is protected in the reducer, including versions and provenance,
rather than merely hiding the browser editor. Placement, comments, deletion and
restore still use ordinary operations. The read-only surface points to the source.

This is the first reading and row-link slice of roadmap-canvas. Automatic refresh,
age/failure indicators, the frame/derive/photograph ladder and a common registry
with Google Docs remain unbuilt. The existing live roadmap-sync timer is unchanged.
