## What landed

### fix(nightly): a file that failed to load is a failure, and the marker is written (isocan-v1d review)

`306863f`

Independent review of 0b215b3e found two ways the gate could still mislead, both
mine, both fixed here with a test that can fail.

**F-1: a test file that failed to LOAD read as a green suite.** `suiteReport()`
counted `assertionResults[].status` only, and vitest reports a transform/import
error as `status: "failed"` on the FILE with `numFailedTests: 0` and an EMPTY
`assertionResults` — so `failed.length === 0`, the gate said "the suite is green",
and the pull request merged. That is the mirror of the 880-failure night: the
environment making the gate pass rather than fail. A failed file is now named
(`<file>: did not run — <first line>`), which also keeps the comparison honest —
a load failure the merge target already has still compares by name — and a
non-zero exit that names nothing is `broken` like a missing report, because an
absence of failures is not an absence of trouble.

**F-2: the comment marker was searched for but never written.** No posted body
carried `nightly-machinery: …`, so `pr view` never matched and every "Left for a
person" comment repeated nightly. `commentOnce` now appends `<!-- <marker> -->`
to the body it posts, and the test hands night one's body back as the PR's
existing comments on night two.

Also in this commit, held from before the review: the bare `--gate` check now
prints WHY it passed (a green that tolerated a red on the merge target is a
different fact from a green suite, which is what persona.yml's call site shows),
and a red gate's added-failure list is capped at 20 with "… and N more" — the
socket-exhaustion night produced an 880-name list that would have been posted
onto somebody's PR.

Verified: 37 tests in test/nightly-prs.test.ts, and both new fixes falsified by
switching them off — 3 red with the fixes removed, green restored.
